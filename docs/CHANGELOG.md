# iM파트너

대구 전통시장·골목상권 소상공인을 위한 웹 기반 경영·금융 도우미입니다.

핵심 방향은 **데이터를 보여주는 서비스에서, 데이터를 행동으로 바꾸는 서비스로**입니다.

## 1. 현재 상태와 다음 목표

### 2026-09-18 추가 수정: 진단 통합·실시간 표시·주변 행사 지도

**이 절이 아래 같은 날의 이전 화면 구성보다 우선합니다.**

- 홈의 영업시간 안내 접두어를 제거하고, 상권 배너를 **‘상권분석 · 매장 앞 상권흐름’**과 요청한 통행·입장·상권 분석 안내 문구로 수정했습니다.
- 매출 요약의 **매출·일평균 매출·순이익·결제 객단가**는 모두 직전 완료월 전체 값입니다. 품목·요일·시간 필터와 현재 시각은 아래 상세 진단에만 적용하며 네 카드에는 적용하지 않습니다. 분석기간은 카드 아래 공통 줄에서 표시합니다.
- 순이익이 크게 보였던 첫 원인은 필터 적용 매출과 월 전체 이익을 한 줄에 섞었던 것입니다. 월간 범위를 통일했고, 추가로 합성 비용 시나리오의 돼지고기 일 매입량·단가와 월 인건비·관리비·기타 지출을 조정했습니다. **2026년 8월 매출 43,085,000원 − 지출 33,790,900원 = 순이익 표시 9,294,100원**입니다. 매입 원자료·지출 진단·보고서·홈 지수는 같은 공유 비용을 읽습니다. 이 설정은 가상의 고깃집 시연값이며 업종 평균·실제 세무상 이익이 아닙니다.
- 접힌 필터는 `전체 품목 / 19시~20시 / 목·금·토`처럼 표시합니다. 상권도 같은 구분자를 사용합니다. 시간 옵션은 ‘전체’, ‘12시~13시’ 형식이며 현재 시간에는 ` - 현재 시간대`를 붙입니다.
- 매출·지출 계산 기준은 짧은 제목과 설명으로 나누었습니다. 계산 기준, 차트 상세, 행사 상세, 추천 기준의 접기 UI는 동일한 여백·글꼴·꺾쇠를 사용합니다.

- 회복전략은 **탭별 단일 고정 화면**입니다. 회복전략 탭에는 ‘회복전략 상세 분석 · 리포트’ 대화 카드만 남기고, 진단별 제안·시간대 참고·독립 기간 선택 영역을 제거했습니다. 페이지 바깥은 스크롤하지 않으며 긴 대화는 카드 안에서 이동합니다. 입력창과 PDF 버튼은 화면 안에 유지합니다.
- 사후관리도 같은 크기의 카드 한 개로 표시합니다. 세 비교 지표는 기본 화면에 모으고, 긴 행동명·근거·메모는 ‘실행 기록 상세’ 창으로 엽니다. 실행 기록은 대화에서 확인한 행동만 사용하며, 기존 저장 기록과 계산 방식은 유지합니다. 실제 데이터 연결이나 자동 실행 기능을 추가한 변경은 아닙니다.

- 홈 운영 안내의 현재 시각과 ‘회복전략 보기’ 링크를 제거했습니다. 시간에 맞춘 안내 내용은 계속 갱신됩니다.
- 매출 시간 필터는 **12시 정오~24시 자정, 1시간 단위**입니다. 실제 시연 매출은 17~23시에 있으므로 나머지 시간의 실적을 새로 만들지 않습니다.
- 매출 화면은 **매출 요약 → 일별 매출 진단·요일별 진단 → 품목별 진단 → 지출 진단**의 4개 섹션입니다. 매입금액 증감도 기존 지표와 같은 ▲/▼ 및 색상을 씁니다.
- 상권 화면은 매출진단과 같은 명명 방식의 **상권 요약 → 시간대·요일별 진단 → 방문·결제 진단 → 주변상권 진단** 4개 섹션입니다. 첫 화면의 4개 지표는 숫자 카드로 표시하고 통행·입장률은 같은 요일 평균과 비교합니다. ‘월간 상권 분석 요약’ 화면은 제거했으며 회복전략에 전달하는 기간 분석 근거는 유지합니다.
- 매출진단·상권분석의 필터는 동일한 디자인의 **상단 고정 바**입니다. 모든 화면 크기에서 꺾쇠 버튼으로 접기·펼치기를 지원하며, 접으면 선택 조건을 한 줄로 보여줍니다. PC는 기본 펼침, 좁은 화면은 기본 접힘입니다. 마지막 섹션에서도 고정하고, 실제 바 높이를 측정해 제목이 가려지지 않도록 합니다. 상권의 요일 선택은 월간 분석에만 적용되며 최근 10분 관측과 독립적입니다.
- ‘지금 우리 가게 앞 상황’의 괄호에는 **서울 현재 시각**을 표시하며 분 단위로 갱신합니다. 완료 관측의 날짜·시간은 별도로 표시하고 관측시간 밖에는 마지막 자료임을 명시합니다. 갱신 시 지도와 스크롤은 유지합니다.
- 주변 흐름은 관측된 시간만 왼쪽 그래프로 표시하고 오른쪽에 **대구 행사 지도**를 배치했습니다. 카카오 지도 연동 코드는 준비했으며, 사용자가 아직 JavaScript 키를 발급하지 않아 현재는 기존 OpenStreetMap으로 선택 행사 위치를 표시합니다. 키 등록 후 카카오 지도·번호 마커로 전환됩니다. 기본 중심은 대구 중구 예시 위치이며 실제 사업장 주소 연결 전입니다.
- 최종 화면 정리에서 **홈을 제외한 모든 메뉴**를 콘텐츠 높이에 따라 연속 스크롤하도록 바꿨습니다. 섹션 여백은 PC 32px·태블릿 24px·모바일 16px, 카드 안쪽은 24px·모바일 18px를 기준으로 통일했습니다. 일별/요일별, 지출, 상권 비교, 주변 흐름/지도, 프로필의 좌우 카드는 같은 폭·높이를 사용하며 작은 화면에서는 쌓습니다. 지원사업과 프로필은 안내·내용을 한 화면 흐름으로 연결했습니다.
- 진단 차트는 **분석 기간 청록 `#137C78` / 비교 기간 회청 `#78869B`**로 통일하고, 증감 ▲/▼ 의미 색상은 유지합니다. 홈은 수정 전후 픽셀 비교로 동일함을 확인했습니다.
- 사용자 제공 **전국문화축제표준데이터.csv** 1,305행에서 대구 56행을 추출하고 같은 일정 중복을 병합해 46개 행사 기록을 연결했습니다. 진행·예정/전체 기록과 거리 필터, 행사 선택 지도 이동, 상세 정보가 동작합니다. 행사장 대신 행정기관을 가리키는 좌표 등 15개는 위치 확인 대상으로 제외하고 31개 등록 좌표를 사용합니다. 원본 날짜·출처를 유지하며 관광공사 API는 사용하지 않습니다. [자료·카카오 설정 안내](prototype/README-nearby-events.md)를 참고하세요.
- 지원사업의 **전체 공고는 공식 원문을 확인한 모든 수집 공고의 세로 목록**이며 10개로 제한하지 않습니다. **맞춤 추천만 조건·접수기간을 검토해 최대 10개를 선정**하고 그 안에서 PC 3개·모바일 1개씩 탐색합니다. 공식 공고 22건의 기관·접수기간·지원 내용·원문 링크를 표시하며, 확인일 2026-09-18의 정적 자료입니다. 자동 수집·실시간 동기화는 연결하지 않았습니다. 상세 근거는 [공고 자료 안내](prototype/README-policy-data.md)를 참고하세요.

검증: 기존 매출 합계 보존, 1시간 구간 합계, 분·10분·자정 갱신, 회복전략 연결, PC·모바일 배치를 검사합니다. 대구 CSV 추출·중복·날짜·좌표 제외, 행사 필터·지도 선택, 필터 접기·고정, 지원사업 카드 탐색을 추가 검증합니다. 카카오 실서비스 인증은 키 발급 후 확인해야 합니다.

### 2026-09-18 최신 회의 반영: 완료된 한 달과 최근 10분 분리

**현재 화면은 이 절을 기준으로 합니다. 아래 이전 기록의 기간·명칭·섹션 구성과 충돌하면 이 절을 우선합니다.**

- 매출진단과 상권 월간 분석은 **한국시각 기준 직전 완료된 한 달**을 사용합니다. 2026년 9월 18일에는 8월 1~31일입니다. 기간 선택은 없고 자료가 없는 날짜를 0으로 채우거나 다른 달로 대체하지 않습니다.
- 매출은 **매출 요약 → 매출 변화 → 요일별 진단 → 품목별 진단 → 지출분석**의 5개 섹션입니다. 번호·매출 변화 분해 카드·요일×시간대 표를 제거하고 일별 비교 그래프를 넓혔습니다. 마지막 지출분석은 가게 전체 지출·구매 내역입니다.
- 매출−지출 차이는 **순이익(추정)**으로 표시합니다. 입력 지출만 반영한 참고치이며 미입력 비용은 제외됩니다. 지출과 추정 순이익에는 품목·요일·시간 필터가 적용되지 않습니다.
- 상권은 **상권 분석 요약 → 주변상권 흐름 → 통행에서 결제까지 → 월간 상권 분석 요약**의 4개 섹션입니다. 첫 화면은 매장 앞 CCTV의 최근 완료된 10분 통행·입장률과 요일별 같은 시각 관측을 보여줍니다. 시간대 선택과 이전 대비 지표는 제거했습니다.
- 최근 결과는 10분 경계마다 갱신하고 시각은 `(19:00)`처럼 표시합니다. 이전 4주 같은 요일·시각의 유효 관측이 3일 이상일 때 ±20% 기준으로 많은 편·적은 편·비슷한 수준을 구분합니다. 실제 CCTV 연결 없이 생성 자료로 동작합니다.
- 주변상권 흐름은 00~23시 전체를 표시하며 자료가 없는 시간은 `—`입니다. 오른쪽 비교 그래프와 하단 행동 안내는 제거했습니다. 통행에서 결제까지를 별도 섹션으로 복원했고 개인별 구매 연결이 없는 전환 비율은 추정치로 표시합니다. 월간 요약 개수는 근거에 따라 달라지며 체류 내용은 제외했습니다.
- 홈·프로필 이름은 **나의 가게 온도**로 통일하고 프로필 팝업의 이동평균 설명 문구를 제거했습니다. 지원사업 확인 순서는 왼쪽 버튼을 눌러 안내창으로 엽니다.
- 좌측 메뉴는 홈·매출진단·상권분석·지원사업·회복전략, 홈 배너는 4개입니다. 회복전략 안의 사후관리 탭, 홈 시간대별 행동 안내, 서비스 설명 전용 iM비서의 3개 FAQ 예시를 유지합니다. 유료 고성능 AI를 사용하지 않는 백엔드 방향도 유지합니다.
- 기존 글꼴·색상을 유지하며 간격을 조정했습니다. PC 1280×720 이상에서 기본 섹션을 한 화면에 배치하고 모바일은 세로로 읽도록 구성했습니다. 7개 화면 크기에서 페이지의 가로 넘침을 검사했습니다.

실제 인증·DB·POS·CCTV·외부 AI 연결은 아직 구현되지 않았습니다. 이번 변경은 로컬 프론트엔드이며 GitHub 배포는 별도입니다. 상세 기준은 [매출진단 개발 안내](16_sales-diagnosis-development.md)와 [상권분석 개발 안내](17_market-analysis-development.md)의 최신 회의 반영 절을 참고하세요.

### 2026-09-18 이전 구현 기록: 월별 진단·홈 안내·서비스 설명 정리

**이 절은 같은 날의 이전 구현 이력입니다. 현재 기준은 위의 최신 회의 반영 절입니다.**

- 좌측 주 메뉴는 **홈 · 매출진단 · 상권분석 · 지원사업 · 회복전략**입니다. 홈 배너는 홈을 제외한 네 메뉴에 맞춘 **4개**이며 내용과 개수만 바꿨습니다. 회복전략 안에 **회복전략 / 사후관리** 탭을 두고 기존 질문·답변·리포트·실행 기록 기능을 연결했습니다.
- 매출진단과 상권분석은 수치·변화·원자료 근거·해석 한계를 보여줍니다. 운영 행동과 추천은 회복전략에서 **매출진단 결과 → 해당 행동 제안 → 상권분석 결과 → 해당 행동 제안** 순서로 정리하며, 두 진단 화면의 선택 조건을 이어서 사용합니다.
- **홈은 행동 안내를 제공하는 예외**입니다. 접속한 한국시각의 시간대에 맞는 ‘지금 할 일’과 ‘다음 시간 준비’를 보여줍니다. 현재 시각에 맞춰 안내를 선택하는 것이며 실제 실시간 매출·상권 데이터가 연결된 것은 아닙니다. 기존 글꼴과 디자인을 유지합니다.
- 두 진단의 분석 범위는 **한국시각 기준 이번 달 1일~오늘**로 고정하고 기간 선택과 필터 아래 비교 날짜 안내를 제거했습니다. 증감 계산에 필요한 이전 기간 비교는 유지합니다. 요일은 기본 단일 선택이며 **복수 선택**을 체크하면 여러 요일을 고를 수 있습니다. 체크를 해제하면 마지막으로 선택한 요일을 유지합니다.
- 시간대는 **17~19시 / 19~21시 / 21~23시** 중 접속시각이 포함되는 구간을 기본 선택하며 직접 변경할 수 있습니다. 영업시간 외에는 전체 시간을 표시하고 영업시간 외임을 알립니다. 초기화도 현재 시간대로 돌아갑니다. 매출·상권의 모든 섹션은 위아래 여백을 줄여 핵심 내용을 한 화면에서 확인하기 쉽도록 맞췄습니다.
- 우측 **iM비서**는 서비스 사용법을 짧게 설명하는 도우미입니다. 예시 질문은 **3개**이며, 현재 프론트에서는 외부 API 호출 없이 FAQ 규칙으로 답합니다. 매출 분석이나 행동전략 생성용 챗봇이 아닙니다. 향후 백엔드도 **FAQ 우선, 필요 시 무료로 이용 가능한 경량 AI**를 검토하고 유료 고성능 AI는 사용하지 않는 방향입니다. 이 방침이 배포·호스팅 비용까지 무료라는 뜻은 아닙니다.
- 각 제안에는 분석 범위와 한계를 표시합니다. 비교가 필요한데 비교 자료가 없거나 현재 자료가 불완전하면 해당 제안을 보류합니다. 상권의 현재 관측만으로 가능한 점검 제안은 이전 기간 비교 없이도 그 범위를 명시해 제공합니다.

5. `iM비서`에서 예시 질문을 선택하고 분석 요약 PDF를 생성합니다.
6. 좌측 하단 사용자 메뉴의 `로그아웃`으로 비로그인 시작 화면에 돌아옵니다.

서버 설치 없이 실행되며 비로그인·로그인·로그아웃은 프론트엔드 화면 전환용입니다. 입력값은 전송·저장되지 않으며 실제 인증·세션·접근 통제, DB, 실제 AI 연결은 없습니다. PC에서는 각 메뉴의 내용을 한 화면 높이 단위로 나누어 이동하고, 작은 화면에서는 일반 세로 흐름으로 표시합니다. 생성 자료 여부는 관련 카드와 주의 문구에 표시합니다. 프로필 변경은 화면과 가상 공고 조건에만 반영되고 생성 POS·CCTV 자료 자체는 바뀌지 않습니다.

## 4. 데이터·해석 원칙

- 최신 사용자 확인에 따라 POS를 포함한 생성 데이터를 공모전 시연에도 사용합니다. ‘시연용 데이터를 없앤다’는 초기 문구는 대체하며 생성 사실을 표시합니다.
- 생성 자료도 거래·품목·기간·계산 일관성을 검증합니다. 자료에 없는 항목을 고정 답변으로 채우지 않습니다.
- DB 저장만으로 실데이터라고 판단하지 않습니다.
- 제한된 카드사·통신사 원자료는 무단 저장·반출하지 않고 허용된 결과만 사용합니다.
- 적법하게 제공받은 POS 자료는 별도 보호 저장하며 개인 자료를 Git에 올리지 않습니다.
- POS 주문·결제 건수, CCTV 통행·체류·입장객, 상권 유동인구를 구분합니다.
- CCTV 분석 결과는 개인을 식별하지 않는 시간대별 집계값만 서비스에 전달하는 방향입니다. 실제 영상 처리·보관·접근 방식은 도입 전에 별도로 확정합니다.
- 매장 유입률은 입장객÷통행자, 추정 구매전환율은 비교 가능한 유효 결제 건수÷입장객입니다. 결제 건수는 구매자 수와 같지 않을 수 있고 배달·비대면 결제가 섞일 수 있으므로 두 번째 지표는 추정치로 표시합니다.
- 매출−지출 차이·회계상 영업이익·현금흐름을 구분합니다.
- 소비 전환 공백은 요인 후보이지 개인의 실제 구매전환율·확정 원인이 아닙니다.
- 이전 시안의 62°와 +650,000원은 산출 근거 미정의 Mock입니다. 현재 화면에서는 해당 점수·금액을 표시하지 않습니다.
- 정책 적합도 %는 산식 확정 전 생성하지 않고 선정 확률로 표현하지 않습니다.
- 내부 테스트 fixture는 서비스 데이터와 격리합니다.

## 5. 개발 방향

예정 기술: Python, Django, Django REST Framework, MySQL.

기존 라이브러리 계획: mysqlclient, django-filter, drf-spectacular, django-environ, pandas, numpy, httpx, openpyxl, Pillow(향후 영수증), pytest, pytest-django, ruff.

순서:

1. CCTV·POS 제공 방식, 익명 집계·중복 기준, 시간대 정합성과 7일 비교 규칙을 확정.
2. DB·인증·공통 분석 구조와 생성/실제 데이터 구분 구현.
3. 생성 CCTV·POS 시연 자료 검증과 기존 P0 연결. 실자료는 확보 후 권한·출처 검증 및 교체.
4. 현재 생성 CCTV·POS 전환 퍼널을 선택 기간·프로필·공통 분석 실행·PDF·영속 7일 비교와 연결하고, 지도·상권 보조 근거를 자료 준비 순서에 맞춰 연동.
5. 화면·그래프·AI챗봇·iM비서/PDF 수치 일치 시험.
6. 실제 구현 상태에 맞춰 발표·Q&A·영상 재제작.

기존 회복 플랜의 P0는 유지합니다. 이번 승인으로 모든 신규 요구의 개발 순위·일정이 확정된 것은 아닙니다.

## 7. 아직 정하지 않은 항목과 제외 범위

[PRD의 확인사항 C-01~C-13](01_prd.md#8-구현-전-확인할-사항)에 실자료 제공 범위, CCTV 처리·집계, 회복 기회·전후 비교 규칙, 지도·경쟁 근거, 정책 점수, 정보 공급원·알림, 상담 채널, 금융 산식, AI·PDF 도구, 블록체인 검토 상태를 기록했습니다. 프로필의 지역은 사업장 소재지, 사업장 규모는 직원 수로 확정했습니다. POS·CCTV 집계 포함 생성 데이터를 공모전 시연에도 쓰되 표시한다는 방침도 확정했습니다.

n8n 도입, 실제 금융상품 신청·신용평가·대출 실행, 외부 유료 API 결제는 이번에 승인·구현하지 않습니다. OCR은 기존 후순위로 유지합니다. 구체 범위가 없는 세무신고 기능은 추가하지 않습니다.

**블록체인은 현재 서비스와 확정 아키텍처에 적용하지 않습니다.** 월간 경영 브리핑의 발급 후 변경 여부를 iM뱅크·소상공인·상담기관 등 독립된 여러 주체가 함께 확인해야 하고, 중앙 감사 기록과 전자서명만으로 충분하지 않다는 요구가 확인될 때에만 `P2 조건부 확장`으로 별도 PoC를 검토합니다. 현재 원장 유형·참여기관·운영 주체·일정은 미확정이며 PoC도 승인되지 않았습니다.

조건부 PoC를 검토하더라도 개인정보·POS/CCTV·금융 원자료와 PDF 원본은 기존의 접근 통제된 저장소에 두고, 직접 식별할 수 없는 검증 ID·보고서 해시·버전·발급 시각 등 최소 정보만 원장 기록 후보로 검토합니다. QR만 조회하면 등록 기록과 버전만 보여주고, 사용자가 PDF를 명시적으로 선택해 기기에서 해시를 계산한 경우에만 **발급 당시 등록본과 현재 파일의 일치 여부**를 판정합니다. 원본 데이터의 사실성·AI 분석 정확성·공식 소명 효력·금융심사 결과를 확인하거나 보장하지 않으며, 단순히 해시값만 생성한 경우에는 블록체인 적용으로 설명하지 않습니다. 상세 조건은 [PRD의 P2 조건부 확장](01_prd.md#p2-조건부-확장-월간-경영-브리핑-변경-여부-확인)과 [조건부 참조 아키텍처](05_system-architecture.md#10-p2-조건부-블록체인-참조-구조현재-미적용)를 따릅니다.
