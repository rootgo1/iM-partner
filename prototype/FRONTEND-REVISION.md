아래 9월 15일 기록 중 홈 구성·가게명·메뉴 순서와 충돌하는 내용은 이 절을 우선합니다.

## 1. 현재 화면

## 2. 시연 자료

- **가게:** 대구 중구의 가상 ‘소현고깃집’, 50대 이소현 사장님. 상세 주소·실제 계정은 설정하지 않았습니다.
- **영업:** 매일 17:00~23:00. 삼겹살·목살·양념갈비·된장찌개·공깃밥·음료의 이름과 가격도 시연 설정입니다.
- **자료 기간:** 2026-06-01~2026-09-30. 실제 매출이나 관측 실적이 아닙니다.
- **원래 집계:** 판매·결제와 매장 전면 통행·체류·입장을 같은 10분 구간으로 연결합니다. 하루 36개 구간이며, 1시간 값을 임의로 나눈 관측값이 아닙니다. 매출진단의 시간대 보기는 이를 17~19시·19~21시·21~23시로 묶습니다.
- **비교:** 선택 기간과 겹치지 않는 이전의 같은 요일 구성으로 비교합니다. 자료가 부족하거나 기준값이 0이면 증감률을 만들지 않습니다.
- **날씨:** 대구 중구, 9월 3일 맑음·26°C의 고정 시연입니다. 실시간 날씨가 아니며 매출 변화의 원인으로 단정하지 않습니다. 가게 온도와 날씨 기온은 별개입니다.

가게 온도는 기존 매출·지출 기반의 최근 30일 참고 지수입니다. 유입률은 입장 관측 ÷ 통행 관측, 결제 전환율은 유효 결제 ÷ 입장 관측의 추정치입니다. 결제 건수는 구매 인원과 다르고 입장·결제 시각도 다를 수 있습니다.

## 3. 실행 기록과 전후 비교

1. iM비서에서 질문을 분석하고 행동지침을 확인합니다.
2. **실제로 수행한 뒤** ‘실행 기록하기’에서 행동지침, 실행일, 대상 시간, 메모를 입력합니다. 권고를 읽거나 PDF를 만드는 것만으로 실행 처리하지 않습니다.
3. 사후관리에서 기록을 선택합니다. **실행일을 제외한 이전 7일과 다음 7일**의 같은 영업시간을 비교합니다. 예를 들어 9월 3일 실행은 8월 27일~9월 2일과 9월 4일~9월 10일을 비교합니다.
4. 매출액을 주지표로, 판매수량을 보조값으로 확인합니다. 여러 행동을 함께 기록하면 하나의 묶음으로 비교합니다. 변화가 특정 행동의 효과라는 뜻은 아닙니다.

실행 기록은 **같은 브라우저·같은 미리보기 주소(포트 포함)**에만 저장됩니다. 새로고침 후에도 남지만 다른 기기와 동기화되지 않으며, 해당 사이트의 브라우저 데이터를 삭제하면 지워집니다. 비교 금액은 모두 시연 자료입니다. 로그인 시연 입력값과 비밀번호는 전송·저장하지 않고 종료 시 지웁니다. 프로필 수정은 현재 화면에만 반영됩니다.

## 4. 실행 방법

별도 앱 빌드나 패키지 설치 과정은 없습니다. 기존 진입 파일은 루트 `index.html`, 로그인은 `prototype/login-preview/index.html`, 본화면은 `prototype/main-screen.html`입니다.

Python이 있는 환경에서 프로젝트 루트의 PowerShell을 열고 다음 명령으로 `prototype` 폴더의 정적 파일만 이 컴퓨터에서 제공합니다.

```powershell
Set-Location -LiteralPath 'C:\Users\rmsgh\Documents\Projects\iM-partner'
python -m http.server 8766 --bind 127.0.0.1 --directory prototype
```

브라우저에서 [시작 화면](http://127.0.0.1:8766/login-preview/index.html)을 열고 ‘데모시작’을 누릅니다. [본화면](http://127.0.0.1:8766/main-screen.html#dashboard)으로 바로 들어갈 수도 있습니다. 서버를 멈출 때는 실행 중인 터미널에서 `Ctrl+C`를 누릅니다. 이 명령은 정적 파일 미리보기이며, 실제 로그인·업무 서버나 배포를 만드는 명령이 아닙니다. `tmp/`의 임시 검사 서버 파일은 실행에 필요하지 않습니다.
