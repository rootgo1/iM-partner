# iM파트너

대구 전통시장·골목상권 소상공인을 위한 웹 기반 경영·금융 도우미입니다.

핵심 방향은 **데이터를 보여주는 서비스에서, 데이터를 행동으로 바꾸는 서비스로**입니다.

## 1. 현재 상태와 다음 목표

### 2026-09-12 회의 수정 반영

로그인 화면의 데모 진입과 임의 입력 성공 처리를 제거했습니다. 인증 서버가 없어 현재는 연결 대기 상태입니다. 메인 UI 검토는 `prototype/main-screen.html`을 직접 열어 진행합니다.

홈은 브리핑·요약 → 시간대별 운영 안내 → 네 지표 그래프·현재 매출진단 → CCTV·POS 순서입니다. 금융지수는 일별 지수의 최근 30일 이동평균으로 갱신하며 자료 기준일을 표시합니다. 상권 소비는 서비스 이용 가게 합계로 분리했고, CCTV 전환율은 전월 동일 요일·시간대와 비교합니다. 현금보유량과 미연결 자금 지표도 추가했습니다.

변경 파일과 검증은 [회의 수정 내역](prototype/MEETING-CHANGES.md)을 참고하세요. 아래 9월 9일 기록보다 이 절을 우선합니다.

추가 수정으로 금융지수 명칭·연결 상태 배치·상권 요약의 증감 표시를 정리했습니다. 시간대별 운영 안내는 최근 30일 일평균과 하루 매출 중 비중을 표시하며, ‘지금 할 일’과 ‘다음 시간 준비’ 두 가지를 안내합니다. ‘주변 상권 흐름’은 최근 30일 중 오늘과 같은 요일의 유동인구·서비스 이용 가게 소비 패턴과 행동 안내를 제공합니다. 오늘 실적이나 수요 예측이 아니며 실제 자료 기준일을 함께 표시합니다.

섹션 내부 스크롤을 없애고 내용이 길면 전체 화면에서 스크롤하도록 조정했습니다. 비교 그래프는 여러 지표를 선택한 상태로 시간대별·요일별 전환이 가능하며, 현재 매출진단은 선택 기간의 2시간 구간 일평균과 매출 비중을 함께 보여줍니다.

2026-09-09 현재 구현을 기준으로 문서 상태를 다시 맞췄습니다. **화면에서 동작하는 생성 데이터 시연과 실제 데이터·서버 연동 완료는 다릅니다.** 이번 최신화에는 홈 4개 섹션, 통합 메뉴명, 프로필 금융 체온계 요약과 비로그인 시작 화면 정리가 포함됩니다. 블록체인 관련 상태는 `현재 미적용 / P2 조건부 확장 / PoC 별도 승인`이며 화면·프로토타입·확정 아키텍처에는 추가하지 않았습니다.

| 구분 | 현재 | 승인된 목표 |
|---|---|---|
| 실행 | 비로그인 시작 화면과 정적 반응형 HTML MVP, 5개 주 메뉴·내 프로필·공통 AI챗봇·로그아웃 왕복 | Django·MySQL 기반 서비스 |
| 데이터 | POS 형식 생성 매출·지출·매입·상권 자료와 공통 계산 | DB 기반 생성자료 시연 후 허용된 실자료 교체 |
| 매출·지출 | 기간별 매출·비용 5분류·매입 TOP 3·요일/시간 분석 | DB POS + 실제 확보 범위의 지출·재고 분석 |

| 정책 | 실제 공고가 아닌 목록·검색·조건 매칭 시안 | 공고 수집·자격 구조화·검증된 추천 |
| 프로필·인증 | 비로그인 진입, 로그인 없는 데모·임의 입력 확인·로그아웃 화면 전환과 새로고침 시 초기화되는 프로필 시안 | 실제 인증·세션·소유권·서버 저장 |

DB, 백엔드 API, 실제 외부 AI, CCTV 영상·장비 분석, 실제 지도, POS 가져오기, 실정책·뉴스·날씨·행사 연동은 아직 구현되지 않았습니다. 현재 CCTV·POS 값은 생성 시나리오이고 PDF는 브라우저에서 생성되는 시연용 파일입니다. 문서에 등장하는 외부 제공처는 실제 연동 완료나 이용 승인을 뜻하지 않습니다.

문서에서는 다음 상태를 구분합니다.

- **현재 구현**: 이 저장소의 정적 프로토타입에서 직접 확인할 수 있는 기능
- **목표**: 구현·검증이 필요한 서비스 요구사항
- **검토 중**: 도입 여부를 결정하지 않은 선택 사항
- **현재 범위 제외**: 이번 구현과 확정 아키텍처에 포함하지 않는 기능

## 2. 사용자 흐름

목표:

가게·기간 확인 → 홈 → 매출진단 → CCTV·POS 전환 흐름 → 요인 후보 → 회복전략 → 실행 → 7일 후 비교.

- 체온계는 홈에 포함하고 프로필 메뉴에 같은 기준의 요약을 표시합니다.
- 회복전략은 CCTV의 익명 통행·체류·입장 집계와 POS 결제·매출을 핵심 근거로 사용합니다.
- 지도·동종업종·상권 고객층·행사는 회복 플랜을 보완하는 맥락 자료이며 핵심 전환율을 대신하지 않습니다.
- AI챗봇은 모든 탭에서 간단한 질문에 답합니다.
- 정책·지원사업은 필요한 경우 연결합니다.
- iM비서는 별도 대화형 분석과 실제 PDF를 제공합니다.
- 프로필·권한은 실제 개인·사업장 자료를 사용할 때 필요합니다.

현재 HTML은 비로그인 시작 화면 → 로그인 없는 데모 또는 임의 입력 확인 → 홈 → 매출진단 → 회복전략 → 지원사업 → iM비서·AI챗봇 → 내 프로필 → 로그아웃 복귀까지 이동할 수 있습니다. CCTV·POS 회복전략은 `2026-09-03` 기준의 별도 고정 생성 시나리오이므로 선택한 기간·프로필에 따라 다시 계산되지는 않습니다. 실행 버튼은 브라우저 안의 상태만 바꾸고 7일 후 실제 결과는 생성하지 않습니다.

## 3. 현재 화면 실행

1. 프로젝트 루트의 `index.html`을 Chrome 또는 Edge에서 엽니다.
2. 서비스 소개와 로그인 입력 검사를 확인합니다. 인증 서버 미연결 상태에서는 홈으로 이동하지 않습니다.
3. 메인 UI 검토는 `prototype/main-screen.html`을 직접 열어 진행합니다.
4. 좌측의 `홈`·`매출진단`·`회복전략`·`지원사업`·`iM비서` 이동과 접기·펼치기, 우측 `AI챗봇`을 확인합니다.
5. `iM비서`에서 예시 질문을 선택하고 분석 요약 PDF를 생성합니다.
6. 좌측 하단 사용자 메뉴의 `로그아웃`으로 비로그인 시작 화면에 돌아옵니다.

서버 설치 없이 실행되며 비로그인·로그인·로그아웃은 프론트엔드 화면 전환용입니다. 입력값은 전송·저장되지 않으며 실제 인증·세션·접근 통제, DB, 실제 AI 연결은 없습니다. PC에서는 각 메뉴의 내용을 한 화면 높이 단위로 나누어 이동하고, 작은 화면에서는 일반 세로 흐름으로 표시합니다. 생성 자료 여부는 관련 카드와 주의 문구에 표시합니다. 프로필 변경은 화면과 가상 공고 조건에만 반영되고 생성 POS·CCTV 자료 자체는 바뀌지 않습니다.

## 4. 데이터·해석 원칙

- 최신 사용자 확인에 따라 POS를 포함한 생성 데이터를 공모전 시연에도 사용합니다. ‘시연용 데이터를 없앤다’는 초기 문구는 대체하며 생성 사실을 표시합니다.
- 생성 자료도 거래·품목·기간·계산 일관성을 검증합니다. 자료에 없는 항목을 고정 답변으로 채우지 않습니다.
- DB 저장만으로 실데이터라고 판단하지 않습니다.
- 제한된 카드사·통신사 원자료는 무단 저장·반출하지 않고 허용된 결과만 사용합니다.
- 적법하게 제공받은 POS 자료는 별도 보호 저장하며 개인 자료를 Git에 올리지 않습니다.
- POS 주문·결제 건수, CCTV 통행·체류·입장객, 상권 유동인구를 구분합니다.
- CCTV 분석 결과는 개인을 식별하지 않는 시간대별 집계값만 서비스에 전달하는 방향입니다. 실제 영상 처리·보관·접근 방식은 도입 전에 별도로 확정합니다.
- 매장 유입률은 입장객÷통행자, 추정 구매전환율은 비교 가능한 유효 결제 건수÷입장객입니다. 결제 건수는 구매자 수와 같지 않을 수 있고 배달·비대면 결제가 섞일 수 있으므로 두 번째 지표는 추정치로 표시합니다.
- 매출−지출 차이·회계상 영업이익·현금흐름을 구분합니다.
- 소비 전환 공백은 요인 후보이지 개인의 실제 구매전환율·확정 원인이 아닙니다.
- 이전 시안의 62°와 +650,000원은 산출 근거 미정의 Mock입니다. 현재 화면에서는 해당 점수·금액을 표시하지 않습니다.
- 정책 적합도 %는 산식 확정 전 생성하지 않고 선정 확률로 표현하지 않습니다.
- 내부 테스트 fixture는 서비스 데이터와 격리합니다.

## 5. 개발 방향

예정 기술: Python, Django, Django REST Framework, MySQL.

기존 라이브러리 계획: mysqlclient, django-filter, drf-spectacular, django-environ, pandas, numpy, httpx, openpyxl, Pillow(향후 영수증), pytest, pytest-django, ruff.

순서:

1. CCTV·POS 제공 방식, 익명 집계·중복 기준, 시간대 정합성과 7일 비교 규칙을 확정.
2. DB·인증·공통 분석 구조와 생성/실제 데이터 구분 구현.
3. 생성 CCTV·POS 시연 자료 검증과 기존 P0 연결. 실자료는 확보 후 권한·출처 검증 및 교체.
4. 현재 생성 CCTV·POS 전환 퍼널을 선택 기간·프로필·공통 분석 실행·PDF·영속 7일 비교와 연결하고, 지도·상권 보조 근거를 자료 준비 순서에 맞춰 연동.
5. 화면·그래프·AI챗봇·iM비서/PDF 수치 일치 시험.
6. 실제 구현 상태에 맞춰 발표·Q&A·영상 재제작.

기존 회복 플랜의 P0는 유지합니다. 이번 승인으로 모든 신규 요구의 개발 순위·일정이 확정된 것은 아닙니다.

## 7. 아직 정하지 않은 항목과 제외 범위

[PRD의 확인사항 C-01~C-13](01_prd.md#8-구현-전-확인할-사항)에 실자료 제공 범위, CCTV 처리·집계, 회복 기회·전후 비교 규칙, 지도·경쟁 근거, 정책 점수, 정보 공급원·알림, 상담 채널, 금융 산식, AI·PDF 도구, 블록체인 검토 상태를 기록했습니다. 프로필의 지역은 사업장 소재지, 사업장 규모는 직원 수로 확정했습니다. POS·CCTV 집계 포함 생성 데이터를 공모전 시연에도 쓰되 표시한다는 방침도 확정했습니다.

n8n 도입, 실제 금융상품 신청·신용평가·대출 실행, 외부 유료 API 결제는 이번에 승인·구현하지 않습니다. OCR은 기존 후순위로 유지합니다. 구체 범위가 없는 세무신고 기능은 추가하지 않습니다.

**블록체인은 현재 서비스와 확정 아키텍처에 적용하지 않습니다.** 월간 경영 브리핑의 발급 후 변경 여부를 iM뱅크·소상공인·상담기관 등 독립된 여러 주체가 함께 확인해야 하고, 중앙 감사 기록과 전자서명만으로 충분하지 않다는 요구가 확인될 때에만 `P2 조건부 확장`으로 별도 PoC를 검토합니다. 현재 원장 유형·참여기관·운영 주체·일정은 미확정이며 PoC도 승인되지 않았습니다.

조건부 PoC를 검토하더라도 개인정보·POS/CCTV·금융 원자료와 PDF 원본은 기존의 접근 통제된 저장소에 두고, 직접 식별할 수 없는 검증 ID·보고서 해시·버전·발급 시각 등 최소 정보만 원장 기록 후보로 검토합니다. QR만 조회하면 등록 기록과 버전만 보여주고, 사용자가 PDF를 명시적으로 선택해 기기에서 해시를 계산한 경우에만 **발급 당시 등록본과 현재 파일의 일치 여부**를 판정합니다. 원본 데이터의 사실성·AI 분석 정확성·공식 소명 효력·금융심사 결과를 확인하거나 보장하지 않으며, 단순히 해시값만 생성한 경우에는 블록체인 적용으로 설명하지 않습니다. 상세 조건은 [PRD의 P2 조건부 확장](01_prd.md#p2-조건부-확장-월간-경영-브리핑-변경-여부-확인)과 [조건부 참조 아키텍처](05_system-architecture.md#10-p2-조건부-블록체인-참조-구조현재-미적용)를 따릅니다.
