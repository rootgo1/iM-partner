# iM 파트너

대구 전통시장·골목상권 소상공인을 위한 웹 기반 경영·금융 도우미입니다.

핵심 방향은 **데이터를 보여주는 서비스에서, 데이터를 행동으로 바꾸는 서비스로**입니다.

## 1. 현재 상태와 승인된 다음 목표

2026-09-03 회의 변경사항을 문서에 반영했습니다. **이번 변경은 문서 수정이며 실제 화면·백엔드 구현 변경이 아닙니다.**

| 구분 | 현재 | 승인된 목표 |
|---|---|---|
| 실행 | 정적 HTML MVP | 기존 디자인을 유지한 데이터 연동 서비스 |
| 데이터 | mock-data.js와 일부 고정 그래프·문구 | POS 포함 생성 데이터로 DB 기반 공모전 시연, 생성 사실 표시; 실자료는 추후 교체 |
| 매출·지출 | Mock 요약 | DB POS + 지출·매입·재고 확보 범위 분석 |
| 체온계 | 대시보드 Mock KPI | 대시보드에서 근거 있는 비교 시각화 |
| 우측 패널 | AI 비서, 규칙 기반 더미 답변 | 챗봇: 모든 탭·크기 조절·간단한 데이터 질문 |
| AI 리포트 | 독립 분석/PDF 미구현 | AI 비서: 대화형 분석→실제 PDF 다운로드·인쇄 |
| 회복 플랜 | 고정 근거·행동 시나리오 | 기존 흐름 + 지도·경쟁 근거·행사·대목 |
| 정책 | Mock 요약 카드 | 공고 수집·자격 구조화·프로필 매칭 |
| 프로필·인증 | 예시 사용자 표시 | 사용자·가게 정보와 소유권 관리 |

DB, 백엔드 API, 실제 외부 AI, 지도, POS 가져오기, PDF 생성은 아직 구현되지 않았습니다. 문서에 등장하는 외부 제공처는 실제 연동 완료를 뜻하지 않습니다.

## 2. 사용자 흐름

목표:

가게·기간 확인 → 대시보드 → 요일·시간/매출·지출 분석 → 요인 후보 → 골목상권 회복 플랜 → 실행할 행동.

- 체온계는 대시보드에 포함합니다.
- 챗봇은 모든 탭에서 간단한 질문에 답합니다.
- 정책·지원사업은 필요한 경우 연결합니다.
- AI 비서는 별도 대화형 분석과 실제 PDF를 제공합니다.
- 프로필·권한은 실제 개인·사업장 자료를 사용할 때 필요합니다.

현재 HTML의 시연 흐름은 가게 확인 → KPI → 비교 그래프 → 고정 회복 플랜 → 더미 AI 비서입니다.

## 3. 현재 화면 실행

1. prototype/main-screen.html을 Chrome 또는 Edge에서 엽니다.
2. 좌측 메뉴 이동·접기·펼치기를 확인합니다.
3. 우측 ‘AI 비서’를 열어 대표 질문 또는 입력 질문을 확인합니다.

서버 설치 없이 실행되며 DB·실제 AI 연결은 없습니다. 현재 Mock 표시를 제거하지 않은 이유는 실제 데이터로 전환하지 않았기 때문입니다.

## 4. 데이터·해석 원칙

- 최신 사용자 확인에 따라 POS를 포함한 생성 데이터를 공모전 시연에도 사용합니다. ‘시연용 데이터를 없앤다’는 초기 문구는 대체하며 생성 사실을 표시합니다.
- 생성 자료도 거래·품목·기간·계산 일관성을 검증합니다. 자료에 없는 항목을 고정 답변으로 채우지 않습니다.
- DB 저장만으로 실데이터라고 판단하지 않습니다.
- 제한된 카드사·통신사 원자료는 무단 저장·반출하지 않고 허용된 결과만 사용합니다.
- 적법하게 제공받은 POS 자료는 별도 보호 저장하며 개인 자료를 Git에 올리지 않습니다.
- 주문 건수·매장 방문자·상권 유동인구를 구분합니다.
- 매출−지출 차이·회계상 영업이익·현금흐름을 구분합니다.
- 소비 전환 공백은 요인 후보이지 개인의 실제 구매전환율·확정 원인이 아닙니다.
- 현재 62°와 +650,000원은 산출 근거 미정의 Mock입니다.
- 정책 적합도 %는 산식 확정 전 생성하지 않고 선정 확률로 표현하지 않습니다.
- 내부 테스트 fixture는 서비스 데이터와 격리합니다.

## 5. 개발 방향

예정 기술: Python, Django, Django REST Framework, MySQL.

기존 라이브러리 계획: mysqlclient, django-filter, drf-spectacular, django-environ, pandas, numpy, httpx, openpyxl, Pillow(향후 영수증), pytest, pytest-django, ruff.

순서:

1. 자료 제공 범위·권한·사업장 규모 등 미정 항목 확인. 프로필 지역은 사업장 소재지로 확정.
2. DB·인증·공통 분석 구조와 생성/실제 데이터 구분 구현.
3. 생성 POS 등 시연 자료 검증과 기존 P0 연결. 실자료는 확보 후 권한·출처 검증 및 교체.
4. 회의 추가 요구를 자료 준비 순서에 맞춰 구현.
5. 화면·그래프·챗봇·AI 비서/PDF 수치 일치 시험.
6. 실제 구현 상태에 맞춰 발표·Q&A·영상 재제작.

기존 회복 플랜의 P0는 유지합니다. 이번 승인으로 모든 신규 요구의 개발 순위·일정이 확정된 것은 아닙니다.

## 7. 아직 정하지 않은 항목과 제외 범위

[PRD의 확인사항 C-01~C-11](01_prd.md#8-구현-전-확인할-사항)에 위젯 이동, 사업장 규모, 실자료 제공 범위, 지도·경쟁 근거, 정책 점수, 정보 공급원·알림, 상담 채널, 금융 산식, AI·PDF 도구를 기록했습니다. 프로필의 지역은 사업장 소재지로 확정했습니다. POS 포함 생성 데이터를 공모전 시연에도 쓰되 표시한다는 방침도 확정했습니다. 위젯 이동은 보류·재확인합니다.

n8n 도입, 실제 금융상품 신청·신용평가·대출 실행, 외부 유료 API 결제는 이번에 승인·구현하지 않습니다. OCR은 기존 후순위로 유지합니다. 구체 범위가 없는 세무신고 기능은 추가하지 않습니다.
